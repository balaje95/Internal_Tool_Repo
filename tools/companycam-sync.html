1 CompanyCam — projects & documents

Create an access token at app.companycam.com/access_tokens (needs a Pro / Premium / Elite plan) and paste the raw token — don't type "Bearer". CompanyCam's API sends no CORS headers, so calls are relayed through this site's own /api/companycam function, which forwards the Authorization header. The token is used from your browser only and is never stored.

Every project is fetched, then one document call per project — paced under CompanyCam's documented 240 GET/minute budget, so a large account takes a few minutes. Projects appear as soon as they're listed; document counts fill in as they arrive, and Stop keeps whatever has loaded.

Offline fallback for when you'd rather not put a token in the browser — run the two calls in Postman/curl and paste the results. Mapping works exactly the same; sync works too, because Zuper is handed the document URL rather than the file.

4 Sync documents to Zuper

Documents are attached to the customer linked to the matched property via POST customers/{customer_uid}/attachments — Zuper has no property-level attachment endpoint, so that is the real target. Zuper stores the CompanyCam document URL rather than a copy of the file, so nothing is downloaded or re-uploaded. A property with no linked customer is reported and skipped.

Where the documents end up: on the CUSTOMER, not the property. Zuper has no attachment storage for properties at all, so a synced document will never show on the property page — that is not a failure. To verify a run, open Customers → the linked customer → Attachments. The log below names that customer for every project it writes.
Re-runs can duplicate. Zuper exposes no "list customer attachments" endpoint, so the tool can't ask the account what is already there. The checkbox above dedupes against a record kept in this browser only — from a different machine, or after clearing site data, the same document will attach again.
