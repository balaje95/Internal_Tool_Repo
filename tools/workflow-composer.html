Every node carries a master_node_uid naming its type in the Workflow Builder's palette. This asks your account's workflow service for that palette, so exported nodes use real IDs instead of the one captured template's.

Trigger payloads

What a trigger actually sends decides every field path in the generated nodes. This reads the run history of the account's existing workflows and keeps one real payload per trigger — so do the action once in Zuper (create the customer, move the job Qualification → Approved), then capture it here.
